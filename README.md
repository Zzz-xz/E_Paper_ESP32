# 局域网三色墨水屏图文工作台

React + TypeScript + Vite 提供图文排版和实时黑白红预览，FastAPI + Pillow + NumPy 完成图片优化与中文合成，SQLite 保存当前显示任务。ESP32 使用 PlatformIO + Arduino + GxEPD2，通过 Wi-Fi 获取完整位面后刷新屏幕。

## 启动网站

需要 Python 3.14 和 Node.js 24。在项目根目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
npm.cmd ci --prefix web
npm.cmd run build --prefix web
.\start.cmd
```

电脑上打开 `http://localhost:8000`。手机和 ESP32 使用 `http://<电脑局域网地址>:8000`，不能使用 localhost。“连接设备”每次打开或点击“刷新地址”时，按当前访问入口、电脑网卡与访问端口动态生成地址；通过局域网访问时优先显示本次已可访问的工作台入口，其他网卡地址折叠展示。本机访问时选择真实 WLAN/以太网地址，避开虚拟网卡。工作台地址属于运行网站的电脑，手机和电脑使用同一地址；ESP32 配网页地址另由设备实时回报，授权链接只对管理员显示。电脑须保持运行，路由器不能隔离这些设备。普通用户显示图文无需登录，重新配网由管理员保护；项目面向可信局域网，不应直接暴露到公网。

Windows 上若本机可访问、同网手机或 ESP32 无法访问，确认当前网络为可信的私有网络后，可在项目根目录的管理员 PowerShell 中执行一次：

```powershell
.\scripts\allow-lan.ps1
```

该规则仅允许本地子网在私有网络上访问 TCP 8000；服务使用其他端口时传入 `-Port <端口>`。需要撤销时执行 `Remove-NetFirewallRule -Name EPaper-LAN-TCP-8000`。若浏览器开启代理，应让工作台的局域网地址使用直连。配网成功仅表示 ESP32 已连接路由器；工作台收到设备心跳后才显示“设备已连接”。

开发界面时可另开终端运行 `npm.cmd run dev --prefix web`，Vite 会将 `/api` 代理到本机后端。前端生产构建由同一个 FastAPI 服务提供，无需单独部署静态服务器。

电脑网页采用轻磨砂玻璃卡片、弹簧按钮和焦点外发光；图片上传、排版渲染和图片解码期间显示流光玻璃加载层，完成或失败后结束。系统开启“减少动态效果”时停用流光与缩放动画；关闭透明效果时使用实色卡片。

## 首次烧录与手机配网

```powershell
.\pio.cmd run --target upload --upload-port COMx
.\pio.cmd device monitor --port COMx --baud 115200
```

将 `COMx` 替换为设备实际端口。首次启动没有网络配置时，串口会显示 `EPaper-...` 配网热点名称、独立热点密码和配网页地址。若启动信息已错过，在串口输入 `setup` 并发送换行即可重新显示并进入配网。

1. 手机连接设备配网热点，打开串口显示的地址。
2. 从自动扫描结果中选择 **2.4 GHz Wi-Fi**，输入密码及电脑工作台地址；也可重新扫描或手动填写名称。
3. 连接成功后，设备把配置保存到 NVS 并关闭热点；手机连接目标 Wi-Fi，点击“返回图文工作台”。该按钮使用本次配置的工作台地址。
4. 网站显示“设备已连接”后即可发送图文。换网络或电脑地址时，可从网页由管理员发起重新配网。

家庭 Wi-Fi 密码只提交给 ESP32，不经过电脑网站，不打印到日志，也不写入 Git。热点连接口令只在配网时通过设备串口提供，请勿把包含口令的串口输出公开发布。启动固件不会主动刷新面板，因此已有画面会保留。

## 配网管理与密码恢复

密码可直接在网站右上角的“管理设置”中完成，无需通过串口或终端输入。两个独立口令均为 **8～32 个字符**，不能相同，不设默认密码：

1. 首次部署时，在运行网站的电脑上通过 `http://localhost:<端口>` 或 `http://127.0.0.1:<端口>` 打开工作台，进入“管理设置”，分别初始化管理员密码和固定恢复口令。首次设置只接受本机访问，局域网用户无法抢先初始化。
2. 管理员验证当前密码后可在网页更新自己的密码；更新立即使旧管理员会话失效，需要用新密码重新验证。
3. 超级管理员口令每套部署只设置一次，之后固定。它只用于重置普通管理员密码，不能直接配置设备网络，也没有修改自身口令的网页入口。

已有部署沿用原口令，无需重新初始化。密码仅保存加盐 PBKDF2 派生值，配置在被 Git 忽略的 `data/` 下；设置后无需重启网站。Vite 开发代理转发真实客户端地址，开发入口同样执行本机初始化限制。

本机维护工具仍可作为可选入口：

```powershell
# 普通管理员：允许重新配网；也可在本机重新设置
.\set-admin.cmd

# 超级管理员：每套部署只初始化一次，固定用于重置普通管理员密码
.\set-admin.cmd --recovery
```

其他系统使用项目 Python 环境执行 `python -m server.admin` 和 `python -m server.admin --recovery`。使用自定义 `EPAPER_DATA_DIR` 时，服务与维护终端须采用同一目录。

普通管理员在“连接设备”中验证口令，点击“重新配网”，等待设备回报后打开授权配网页。设备保留当前局域网连接，并开启受保护的配置热点；授权链接及管理员会话有效期均为 10 分钟，请勿分享链接。配网页直接向 ESP32 提交网络密码，设备端也会校验短期授权。无需更改时可点击“取消配网”恢复正常显示。设备正在刷新时不能发起配网；设备离线时无法接收网页指令，可等待自动开启配置热点或通过本机串口恢复。

忘记普通管理员密码时，在“管理设置”的超级管理员区域，或“连接设备”的“忘记管理员密码？”中，用超级管理员恢复口令验证后设置新密码。超级管理员登录态只允许重置普通管理员密码，不能调用重新配网接口；重置立即使旧普通管理员会话失效。网页和初始化工具均不提供覆盖已固定超级管理员口令的入口，请离线妥善保存该口令。

## 上传、预览与显示

编辑画布与实屏预览并排显示，边框内为 400×300、4:3 的有效显示区域。属性按当前选中元素展示，统一使用 4/8/12/16 像素间距；小屏可放大编辑，也允许必要的滚动。

- 支持静态 JPEG、PNG、WebP；上限 10 MB、4000 万像素。透明区域使用所选背景色，自动修正 EXIF 方向。
- 支持一张图片及最多 12 段独立文字，可仅图片、仅文字或混排。文字支持简体中文、英文、数字、换行、字号与黑白红墨色；水平左/中/右和垂直顶端/居中/底端可独立组合，作用于文本框内部。
- 新增文字只放在空白区，图片的框位置、尺寸、缩放与调色设置保持不变。空间不足时提示手动调整图片框留出位置，文字不覆盖图片区域；合成时图片层在下、文字层在上。拖动元素移动，拖动右下角缩放，也可输入精确 X/Y/宽/高，单位为屏幕像素。图片框默认锁定当前宽高比例，可取消锁定；图片框与文字框均可相对屏幕六方向对齐，与文字框内部对齐独立。
- 前景色、背景色可从黑白红中选取不同颜色，支持一键交换。新文字默认跟随前景色，也可指定固定墨色；画布空白、透明区域及图片留白采用背景色。图片保留原本明暗，不随配色交换而反相。
- 选中图片后，在图片区域滚动鼠标滚轮可围绕指针缩放框内内容，范围 25%～400%；属性区可调整倍率或恢复 100%。缩放不改变图片框，后端仅采样可见区域，最终帧尺寸不变。
- 图片放大超过 100% 后，按住左键拖动框内图片可调整取景，框的位置和尺寸保持不变；拖动边框或按住 Shift 拖动可移动整个图片框。拖动时编辑区直接绘制本地原图取景，按浏览器绘制帧合并指针事件，不等待后端返回；后端三色预览请求按 120 毫秒间隔合并，松手时提交最终位置。实际可发送的三色画面以右侧最新完成的预览为准，拖动期间禁止发送。
- 双击文字框可原位输入，Enter 换行、Ctrl+Enter 或失焦完成、Esc 撤销本次文字输入；中文输入法组词期间不会触发快捷键。选中文字框后按 `+` / `−` 增减字号，`Ctrl+↑` / `Ctrl+↓` 在画布和原位输入时均可调整字号（8～72），也可直接键入属性区字号。小屏可通过“放大编辑”输入。
- 顶部“快捷键说明”按钮可打开操作说明，列出键盘移动、字号、文字编辑、取色取消和鼠标取景操作；关闭弹窗即可返回编辑，内容保持不变。
- 新上传默认完整显示，保留横竖图片的全部构图且不拉伸，空余区域采用所选背景色；选中图片后，属性区顶部的“图片方向”支持左转／右转 90°，或直接选择 0°、90°、180°、270°，预览自动更新。也可选择铺满裁剪，以及平滑或最近邻像素画缩放。画布留白与图像转换产生的白色光晕分别处理，真实的眼睛、牙齿及高光会保留。
- 自动优先保留红橙色，否则选择主要彩色区域映射为红色；重点色内部有明显明暗分组时保留亮部，配合局部对比区分相近颜色与细线。也可从原图取色、更改色相、红色强度、亮度、对比度和网点抖动。
- 灰度图默认保持黑白明暗，可主动选择“灰度图红色风格化”。
- 上传时分析明暗、边缘与颜色，只计算一次初始建议参数。此后当前参数优先，改变尺寸、裁剪或配色不会擅自覆盖用户的调色；需要辅助时点击“自动推荐参数”，建议应用一次后回到手动调整。默认关闭网点抖动，后续推荐沿用用户的抖动选择。推荐仍先粗筛有限候选，再按输出尺寸评估明暗与细节，不识别或补画具体物体。
- 原生数组运算完成色相、明度、三色映射与位面打包；白洞与孤点按原图局部对比判断，保留既有细线和高光规则。几何采样与调色分开：裁剪、旋转、缩放变化时才重新准备细节，连续改变亮度、对比度和红色强度时复用采样；修改文字或只移动图片时复用图片三色结果。服务仅缓存最近一个已解码原图、几何采样和图片结果，内存不随滑块操作次数持续增长。复杂图片不能无损还原，可通过放大裁剪改善过小细节。
- 修改参数、文字或位置自动更新预览；连续编辑按约 40 毫秒合并，单页面串行请求且始终优先最新意图。拖动期间可持续查看已完成的中间帧，角落显示流光更新提示；中间帧不回写用户参数，也不能发送。停止操作后以最终参数生成预览，用户确认后点击“发送到屏幕”，发送与预览使用同一份位面。
- 图片取色时在指针旁显示原图局部、中心像素与 RGB/HEX，放大镜本地更新并适配旋转、缩放与裁剪；点击或触摸松手后才确认重点色，右键、Esc 或退出按钮取消取色，不提交悬停颜色。文字独立按指定墨色绘制，不参加图片抖动。
- 中文由随项目提供的 Noto CJK 字体在后端统一测量和绘制，编辑区使用同一文字栅格。网页文字框随内容和字号在空白区域内扩展，必要时向屏幕内移动或换行，避免切除文字。400×300 区域无法容纳完整内容时提示缩小字号、精简文字或手动调整图片框，阻止发送未完成的预览。
- 每次下发完整 400×300 帧：黑、红位面各 15000 字节，总计 30000 字节；逐行、高位在左，1 表示前景，位面互斥，其余为白色。设备校验长度、CRC32 和位面互斥后才显示。
- 一次只处理一个发送任务。网站显示已接收、下载、刷新、完成或失败；网站和固件均限制两次刷新启动至少相隔 30 秒，期间仍可上传和预览，刷新尚未结束时仍需等待完成。完成表示设备结束刷新流程，真实面板的颜色和残影仍需目视确认。
- 底部“查看屏幕当前画面”在弹窗中读取一次设备最近确认成功的画面，显示确认时间，关闭后返回编辑，不自动刷新图片。查看间隔为 5 秒，与屏幕的 30 秒刷新冷却独立；新任务或失败任务不会覆盖上次确认的画面。屏幕不支持图像回读，离线、断电或刷新过程中需以实屏为准。

原图仅在电脑服务内存中缓存，最多 4 张、闲置 30 分钟过期，不写入磁盘。最多保留 8 个会话的最新预览、有效 30 分钟，连续调参替换同一会话预览；服务重启后需重新上传。网页排版草稿不持久化。SQLite 仅保存当前任务及冷却时间；网络操作有超时和每轮 3 次重试，设备无任务时每 2 秒轮询。中断下载不会刷新半张图片，自动预览不会触发实体屏刷新。

ESP32 按已到达的数据批量读取位面，每次帧体接收总期限为 5 秒，不随零碎数据延长；HTTP 连接、响应超时分别为 2 秒、3 秒，最多尝试 3 次。联网运行时关闭 Wi-Fi 调制解调器省电以降低收图延迟，适用于持续供电的工作台。串口记录下载耗时、接收失败字节数、信号强度和面板刷新耗时，便于区分网络等待与面板实际刷新。网站接收任务、下载和刷新期限分别为 15、45、120 秒，重复下载轮询不延长期限；具体下载或校验错误会显示在网页。

## 接口与模块

| 接口 | 用途 |
| --- | --- |
| `POST /api/render` | multipart 图片与 JSON `options`，返回预览标识、PNG 和颜色统计 |
| `POST /api/images` | 上传一次原图，返回图片标识、推荐参数与初始预览 |
| `POST /api/images/{id}/render` | 复用内存原图生成图片预览 |
| `POST /api/documents/render` | 合成可选图片与文字列表，返回最终预览及编辑图层 |
| `POST /api/display-jobs` | JSON `preview_id`，创建唯一显示任务 |
| `GET /api/status` | 设备连接、当前任务及冷却倒计时 |
| `GET /api/display/current` | 最近确认完成的画面和确认时间；5 秒内重复获取返回 429，附带 Retry-After |
| `POST /api/device/poll` | 设备心跳和任务获取，无任务返回 204 |
| `GET /api/device/jobs/{id}/frame` | 下载固定 30000 字节位面 |
| `POST /api/device/jobs/{id}/result` | 回报 refreshing、completed 或 failed |
| `GET /api/security/status` | 管理口令配置状态及当前访问是否可首次初始化 |
| `POST /api/admin/initialize` | 仅电脑本机网页首次设置管理员密码，不能覆盖已有密码 |
| `POST /api/recovery/initialize` | 仅电脑本机网页首次设置固定恢复口令，不能覆盖已有口令 |
| `POST /api/admin/password` | 已验证的普通管理员修改密码，旧会话随即失效 |
| `/api/admin/{login,status,logout}` | 普通管理员验证、状态与退出 |
| `/api/recovery/{login,status,logout,reset-admin}` | 超级管理员验证及普通管理员密码重置 |
| `GET/POST /api/device/setup` | 管理员查询或下发重新配网指令 |
| `POST /api/device/setup/{id}/result` | 设备回报动态配网页地址及临时授权 |

后端 `server/` 按参数模型、图像转换、存储和 API 分层。固件入口只做流程调度，配网、HTTP 通信和屏幕访问各自独立。上传参数在 API 边界校验，网络帧在设备通信模块入口校验，显示层消费已验证的位面。

图文文档增加 `foreground`、`background`，默认 `black`、`white` 且不得相同；文字 `color` 可用 `foreground` 跟随前景色。图片 `zoom` 范围 0.25～4，`offset_x`、`offset_y` 为相对图片框宽高的偏移，范围 -3～3，默认 0；`recommendation` 为 `auto` 或 `manual`，旧接口缺省保持 `manual`。渲染响应通过 `applied_options` 返回实际使用的图片参数。图片框比例锁定仅属于编辑状态，不进入设备协议。

网页创建的文字使用 `auto_size: true`，响应 `text_boxes` 按文字标识返回最终框尺寸与位置，前端与实际位面同步使用；空间不足返回 422，不生成被裁切的文字预览。旧接口缺省 `auto_size: false`，保持调用方指定框及溢出警告，便于兼容已有请求。

## 验证

```powershell
.\.venv\Scripts\python.exe -W error -m pytest -q
npm.cmd run build --prefix web
.\pio.cmd run
```

测试覆盖三色映射、灰度图、透明图片、像素画、旋转、预览与位面一致性，以及任务状态、失败、重启持久化和冷却限制。浏览器和硬件验证需要实际浏览器与设备，不能仅凭单元测试认定硬件已显示。

PATH 中有 `g++` 时，测试会使用 `-Wall -Wextra -Werror` 编译并运行固件同一份收图循环，覆盖分片、断流、零碎数据及硬期限；未安装编译器时该项显示跳过。

## 硬件范围

工程面向经典 ESP32，使用 `esp32dev` 配置和 4 MB Flash。更换开发板时需核对实际 ESP32 芯片及 Flash 容量。CH340 是 USB 转串口芯片，不能据此判断 ESP32 的具体型号。

目标屏幕为微雪 4.2inch e-Paper (B) V2 的 SSD1683 版本，400×300、黑白红。对应的 GxEPD2 驱动选型为 `GxEPD2_420c_GDEY042Z98`，图形封装使用 `GxEPD2_3C`。同名产品存在历史版本，后续更换屏幕时需重新核对控制器。

网络固件收到完整有效的任务后全屏刷新一次，随后让屏幕休眠并保持联网。三色屏刷新时闪烁属于正常现象，请等待刷新完成。

屏幕只支持黑白红，设备接收网站生成的位面，不在运行时解码原图或进行颜色转换。固件启动时保留面板已有画面，联网后等待网站显示任务。

| ESP32 GPIO | 驱动模块 | 用途 |
| --- | --- | --- |
| 3V3 | 3V3 | 电源 |
| GND | GND | 共地 |
| 27 | SI | SPI MOSI |
| 26 | SCK | SPI 时钟 |
| 25 | CS | 片选 |
| 33 | DC | 数据/命令 |
| 32 | RES | 复位 |
| 35 | BUS | BUSY 状态输入 |

开发板 D 编号按同号 GPIO 解释。GPIO35 仅支持输入，没有内部上下拉。程序使用上述自定义 SPI 引脚、4 MHz SPI 时钟和 2 ms 复位脉冲。双色分页缓冲使用 6400 字节，不需要整屏缓冲。

## 编译与串口

在项目根目录打开 PowerShell：

```powershell
# 编译
.\pio.cmd run

# 枚举串口，查找 USB-SERIAL CH340
.\pio.cmd device list

# 生成或更新 VS Code C/C++ 的编译数据库
.\pio.cmd run --target compiledb
```

VS Code 可按 `Ctrl+Shift+B` 编译，在“终端 → 运行任务”中选择串口枚举、上传和串口监视任务。无需另外安装 PlatformIO 扩展；C/C++ 扩展通过编译数据库获取头文件路径。

确认开发板型号和目标端口后，可上传显示固件。以下 `COMx` 需替换为实际的 CH340 端口：

```powershell
.\pio.cmd run --target upload --upload-port COMx
.\pio.cmd device monitor --port COMx --baud 115200
```

固件输出初始化、刷新和休眠日志；库的硬件诊断也会输出到串口。出现 `Busy Timeout!` 时，应检查屏幕版本、接线和供电，不能仅凭流程结束日志判断显示成功。屏幕实际画面需要目视确认。

`Ctrl+C` 退出串口监视器。上传前关闭占用同一端口的串口监视器。若上传停在 `Connecting...`，可按住 BOOT，连接建立后松开。工程当前限制为 30 秒；微雪建议此型号常规刷新间隔至少 180 秒，30 秒属于更短的工程设置，并非厂商建议间隔。

## 环境复现

需要 Python 3 和网络连接，在项目根目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\pio.cmd run
.\pio.cmd run --target compiledb
```

Python 依赖由 `requirements.txt` 与 `requirements-dev.txt` 固定，前端依赖由 `web/package-lock.json` 锁定，ESP32 平台与库由 `platformio.ini` 固定。`.venv/`、`.platformio/`、`.pio/`、`web/node_modules/`、`web/dist/`、`data/` 都不提交 Git。临时分析或验证文件统一放入 `temp/`。可用环境变量 `EPAPER_DATA_DIR` 更改运行数据目录，示例文件中的占位配置不包含私人凭据。

源码、网页资源和中文提示统一保存为 UTF-8；C/C++、Python、前端源码使用 LF，Windows 批处理使用 CRLF。检查网页编码时需同时检查 HTTP 字符集声明与实际资源字节。
